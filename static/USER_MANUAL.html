Overview

What is this tool?

The Modbus Server Simulator replaces a physical PLC or field device on your network. It responds to any standard Modbus TCP client exactly as a real device would — letting you configure registers, data types, and scaling without touching hardware.

🔌

Real Modbus TCP Server

Responds to any Modbus TCP client on port 5020. Coils, discrete inputs, holding and input registers — all supported.

📊

Live Web Dashboard

Monitor register values in real time from any browser on the network. No software installation needed on your PC.

⚙️

Fully Configurable

Define register names, data types, scaling, and bit fields through the web interface. Changes apply instantly.

🔄

Byte Order Control

Switch endianness on the fly. Test Big Endian, Little Endian, Modicon word order — no restart required.

📐

Multi-Register Types

Supports 16, 32 and 64-bit integers, IEEE 754 floats, booleans, and bit-field word extractions.

💾

Import / Export

Save and load register configurations as JSON or CSV. Easily share configurations between projects.

When to use this page

Use the Server Registers page when your SCADA client is reading unexpected values. Compare the raw hex value here with what your client receives — if they differ, there is a byte-order mismatch. Use the byte order checkboxes to correct it.

✅

32 and 64-bit registers span multiple rows — one row per 16-bit word. For a float32 at offset 7, you will see two rows: offset 7 (high word) and offset 8 (low word). The bit expansion is available for each word individually.

Reference

Byte Order

Modbus is a 16-bit protocol. When a value is wider than 16 bits (e.g. a 32-bit float), it must be split across two or more registers. Different manufacturers store these words in different orders. The simulator supports all common conventions.

Why it matters

If your SCADA system reads a float32 and gets a nonsense value like 2.524 × 10³⁸ instead of 85.5, the word order is wrong. Toggle the byte order flags until the value is correct — no config change or restart needed.

FlagWhat it does
Big EndianControls byte ordering. Big Endian (default) stores the most significant byte first across the entire value — even for multi-register values such as a 32-bit float spanning two registers. Does not affect which register comes first; that is controlled by First Word Low.
First Word LowFor 32 and 64-bit values: the least significant 16-bit word is stored at the lower register address (words are swapped). Byte order within each word is unchanged. Common in Allen-Bradley and some Siemens devices.
First Double Word LowFor 64-bit values only (4 registers): the low 32-bit double-word is stored first (the two pairs of registers are swapped). Has no effect on 16 or 32-bit values.
ModiconReverses all 16 bits of each register independently — bit 0 becomes bit 15, bit 1 becomes bit 14, and so on within each 16-bit word. Can be combined with the other flags.
✅

Practical approach: Start with all flags unchecked (Big Endian default). Read a known value (e.g. a float32 set to exactly 1.0) from your Modbus client. If the value is wrong, toggle First Word Low. For 64-bit values that are still wrong, also try First Double Word Low. Use the Server Registers page to inspect the raw hex and verify.

Scaling

Scaling lets you store real-world engineering values as integers, which is common in Modbus devices that cannot natively send floating-point numbers.

Scale factor

The physical value is divided by the scale factor before being stored in the register. Your Modbus client reads the raw integer and must multiply by the scale to recover the real value.

Physical valueScaleRaw register value
4.20 bar0.01420
23.7 °C0.1237
1 500 RPM11500

Min / Max range mapping

An alternative to Scale. You define a physical range and a raw register range, and the simulator performs the linear mapping automatically.

ExampleMin ValueMax ValueRaw range
Pressure 0–16 bar0160 – 65535 (uint16)
Temperature −40 to +85 °C−40850 – 65535 (uint16)
ℹ️

Scaling does not apply to float types. If your register is float32 or float64, the value is stored directly in IEEE 754 format — no scale or min/max is needed.

Quick Reference

Common Tasks

Add a new register

  1. Go to Config Editor
  2. Find the panel for the memory area you need (e.g. Holding Register)
  3. Click Add Register at the bottom of the panel
  4. Fill in the Name, Offset, Type, and any scaling fields
  5. Click Save to File — the register is live immediately

Check what your SCADA client actually reads

  1. Go to Server Registers
  2. Locate the register by name or Modbus address
  3. Note the hex value in the Raw Value column
  4. This is exactly what your Modbus client receives

Fix a wrong float value from my PLC

  1. Set a known value (e.g. a float32 with a recognisable number)
  2. Check raw words on the Server Registers page
  3. Toggle First Word Low on the Monitor page
  4. Re-read from your PLC/SCADA
  5. If still wrong, try Modicon instead

Export and share my configuration

  1. Go to Config Editor
  2. Click Export JSON to download the full configuration file
  3. Send the file to a colleague — they can import it with Import JSON

Troubleshooting

SymptomLikely causeFix
Monitor shows red dot / "Connection error" Container has stopped Check that the Docker container is running. Restart it if needed.
Modbus client cannot connect Port 5020 not reachable Verify the container exposes port 5020. Check firewall rules on the host machine.
Client reads wrong value for a float Byte / word order mismatch Toggle First Word Low or Modicon on the Monitor page.
Register missing from Monitor Validation error in config Go to Config Editor — invalid registers are highlighted. Check for duplicate offsets or wrong type for coil/DI.
Two registers seem to conflict Multi-register type overlapping another register A float32 at offset N occupies offsets N and N+1. Move the conflicting register to a free offset.
